# todoList 완성 및 변경 설명

## 기존 진행 상태
- index.html, index.css, index.js, render.js로 화면과 동작을 분리했습니다.
- 추가 버튼, 전체/남은 일/끝낸 일 필터, 완료 체크, 개별 삭제가 작성되어 있었습니다.
- 완료 항목 일괄 삭제는 비어 있었고, Enter 제출·저장·진행률 갱신은 연결되지 않았습니다.
- 필터 결과의 순번으로 원본 배열을 변경하여 다른 할 일을 체크하거나 삭제하는 오류가 있었습니다.

## 수정 및 추가한 부분
코드에서 `[추가]`, `[수정]`을 검색하면 변경한 부분과 이유를 확인할 수 있습니다.

| 파일 | 변경 내용 |
| --- | --- |
| index.js | 고유 ID로 항목 식별, 통합 render 함수, 필터 유지, 완료 항목 일괄 삭제 |
| index.js | form 제출, 공백 입력 차단, 한글 조합 중 Enter 처리, 입력창 포커스 |
| index.js | localStorage 저장·복원 및 오류 안내, 날짜·진행률·버튼 상태 갱신 |
| render.js | 입력 문자열의 HTML 특수 문자 변환, 필터별 빈 목록 문구, 올바른 li 구조 |
| index.html | 한국어·제목 설정, form 및 접근성 속성, 진행률과 저장 오류 안내 연결 |
| index.css | 외부 reset.css 의존성 제거, 목록·진행 막대·모바일 줄바꿈·포커스 스타일 |
| index1.html | 정적 시안의 잘못된 CSS 경로 수정, 없는 app.js 연결 제거, 완성 앱 링크 추가 |

root.css와 index1.css는 유지했습니다. index1.html은 정적 시안이며 실제 앱은 index.html입니다.

## 핵심 원리

### 1. 배열 순번 대신 고유 ID 사용
원본 배열이 A, B, C이고 A가 완료되어 있으면 남은 일 화면은 B, C입니다. 이 화면에서 B의 순번은 0이지만 원본 배열의 0번은 A입니다. 이전 코드는 B를 눌러도 A를 변경할 수 있었습니다. 이제 각 항목의 id를 data-id에 넣고 find/filter로 원본 항목을 찾습니다.

### 2. 상태 변경 후 저장 → 화면 갱신
commit()은 saveTodos()와 render()를 호출합니다. render()는 현재 필터로 목록을 만들고 전체 목록의 완료 개수로 진행률과 삭제 버튼 상태를 갱신합니다. 같은 화면 갱신 코드를 여러 이벤트에서 반복하지 않습니다.

### 3. Enter와 클릭 통합
form의 submit 이벤트는 추가 버튼과 Enter 양쪽에서 발생합니다. preventDefault()는 페이지 새로고침을 막고 trim()은 앞뒤 공백을 제거합니다. 입력창은 자바스크립트에서 직접 비웁니다. 버튼에 type="submit"을 지정하는 것만으로 입력값이 지워지는 것은 아닙니다.

### 4. 저장과 안전한 화면 표시
localStorage에 JSON 문자열로 저장합니다. 같은 브라우저와 같은 주소에서 다시 열면 복원됩니다. 저장소 사용이 제한되면 안내를 표시하고 현재 세션에서는 계속 사용할 수 있습니다. render.js는 사용자 입력의 <, >, & 등의 문자를 변환하여 입력이 HTML 코드로 실행되지 않게 합니다.

## 실행 방법
VS Code에서 해당 폴더의 index.html을 Live Server로 실행하세요. ES 모듈을 사용하므로 파일을 더블클릭하는 file:// 방식보다 HTTP 서버로 실행해야 합니다. 브라우저나 서버 주소·포트가 달라지면 localStorage 저장 공간도 달라집니다.

## 검증 결과
Chrome에서 공백 입력 차단, Enter 추가, 필터 상태에서 체크·개별 삭제, 완료 일괄 삭제, HTML 문자 표시, 새로고침 저장 복원, 손상된 저장 데이터 처리, 320px 화면의 가로 넘침 여부를 확인했습니다. 검증 중 JavaScript 실행 오류는 없었으며 JS 구문 검사도 통과했습니다. 한글 IME 동작은 방어 코드를 추가했으며 실제 한글 키보드 조합 입력은 자동 검증 범위에 포함하지 않았습니다.
